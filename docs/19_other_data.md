# MVP 14-8단계: 다른 데이터와 사용자 파일 (2026-10-17)

Can·Square 말고도 분석·진단·선별·학습 키트가 되는지 robomimic **Lift MH**(큐브 들기, 여러 사람 300개, 약 51MB)로 확인했다. 같은 파일을 사용자가 올린 파일로도 넣어 봤다.

## 결과 (실제 대화, 게시된 Dify)
| | Can MH | Lift MH | 올린 파일 (Lift 파일을 `my_robot_data.hdf5`로) |
|---|---|---|---|
| 위치 편중 (같은 넓이 칸) | 가운데 몰림, 부족한 칸 4개 | 고르게 퍼짐, 부족한 칸 없음 | 같음 |
| 거의 같은 시범 (2cm 미만) | 0쌍 (가장 가까운 2.6cm) | **632쌍** (가장 가까운 0.8cm) | 같음 |
| 추천 개수 | 135 (실험 근거) | 없음 → 기본 150, "근거 없음" | 없음 → 기본 150 |
| 학습 키트 | 원본 내려받기 가능, 약 40분 | 원본 내려받기 가능, 시간 측정 안 됨 | **원본 없음 → 키트의 데이터 파일 필요**, 시간 측정 안 됨 |

- 진단이 데이터마다 다르게 나온다. Lift는 쉬운 작업이라 시범들이 서로 매우 비슷하다 (중복 진단이 의미 있게 나온 첫 데이터)
- 선별 방법은 그대로다 (중복은 보고만 함). 중복을 빼면 Lift 학습이 나아지는지는 실험하지 않았다
- Lift는 학습 실험을 하지 않아 근거표에 없다. 카드·보고·키트가 모두 "근거 없음"과 "비교 학습 노트북으로 직접 확인할 수 있음"을 알린다
- 목록(catalog)의 lift_mh를 "분석·선별 해 봄(tested)"으로 바꿨다

## 바꾼 것
- **데이터 올리기** (`POST /api/data?name=<파일>.hdf5`, 웹 데모의 [내 데이터 올리기]): 영문·숫자·`_.-` 이름의 `.hdf5`만, 2GB 이하, HDF5 서명과 robomimic 형식(`data` 그룹에 시범) 확인, 아니면 바로 지움. 같은 이름은 번호를 붙여 덮어쓰지 않는다. 올리면 요청 문장에 "내 파일 <이름>에서 학습할 시범 골라줘"를 넣는다
- **데이터 이름을 코드가 읽기**: 모델(Gemma)이 "lift_mh로 골라줘"에도 데이터 제안 도구를 불렀다. 예산 숫자처럼 근거 정리 노드가 요청 문장에서 데이터 이름(`lift_mh` 등)과 올린 파일 이름(`*.hdf5`)을 읽어 에이전트 안내문에 넣는다. `suggest_datasets`도 이름이 있으면 후보 대신 "분석하라"를 돌려준다 (한글 조사가 붙어도 인식)
- 에이전트 안내문: 올린 파일 이름은 `analyze_data`의 `file_name`에 그대로, 이름을 말했으면 제안 도구를 부르지 않는다
- 추천 없음 이유를 존댓말로, Lift 물체 이름 "큐브"

## 확인
테스트 67개 통과 (데이터 올리기 5가지, 이름 인식). 실제 대화로 Lift 이름·올린 파일·Can(회귀)을 확인.
