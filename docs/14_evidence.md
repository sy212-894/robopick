# 근거표와 추천 개수 (2026-10-17)

## 왜
지금까지는 선별 뒤 매번 학습해서 결과를 봐야 잘 골랐는지 알 수 있었다. 그러면 사용자가 직접 학습하는 것과 다르지 않다.
새 흐름에서는 학습 없이 선별 결과를 바로 주고, "이 방법으로 고르면 무엇이 확인됐는지"는 지금까지 한 실험으로 보여 준다.
사용자가 몇 개를 써야 할지 모르는 게 보통이라, 개수도 실험 결과로 추천한다.

## 근거표 (`results/evidence.json`)
`python -m curation_tools.evidence --build`로 실험 결과 파일에서 만든다. 판정은 기존 코드(`paired_report`, `seeds_report`)가 계산한 값 그대로다.

| 데이터 · 개수 | 선별 - 무작위 (주 판정) | 전체 - 선별, 하락 5%p 이내 확인 (신뢰구간 위쪽 끝) | 실험 |
|---|---|---|---|
| Can 60 | +21.0%p 차이 있음 | 아니오 (+8.9%p) | 예산 60 1차 (docs/12) |
| Can 135 | +5.3%p 구분 불가 | 예 (-6.9%p) | docs/09 |
| Can 150 | +13.7%p 구분 불가 (추가 분석 시드 5개: +20.0%p 차이 있음) | 예 (+3.9%p) (추가 분석 시드 5개: 아니오, +5.8%p) | docs/07, 11 |
| Square 150 | +10.7%p 차이 있음 | 예 (+0.6%p) | docs/06 |

하락 기준 "확인"은 1주차 기준 그대로 짝지은 비교 신뢰구간의 위쪽 끝 ≤ +5%p다.

## 추천 규칙 (예산 60 2차 결과를 보기 전에 커밋)
1. 전체 대비 하락 5%p 이내가 주 판정으로 확인된 개수 중 가장 작은 개수
2. 없으면 선별이 무작위보다 높다고 주 판정으로 확인된 개수 중 가장 큰 개수
3. 둘 다 없으면 추천하지 않는다 (기본값 150을 쓰되 근거 없음을 알림)

지금 결과: Can 135개, Square 150개. 실험하지 않은 데이터(예: 사용자 파일)는 추천 없음.

요청한 개수가 표에 없으면(`lookup`) 바로 아래·위 개수의 결과를 "참고, 이 개수는 확인 안 됨"으로 붙인다. 예: Can 100개 → 60개·135개 결과.

## 한계
- 실험은 Can(60·135·150)과 Square(150)뿐이다. 다른 개수나 다른 데이터에는 "가까운 결과" 또는 "근거 없음"으로만 말할 수 있다
- 예산 60 2차(기준선 6개)는 선별·무작위·전체 비교를 바꾸지 않으므로 추천 개수에는 영향이 없다. 결과가 나오면 근거표에 기준선 비교로 덧붙인다
