# MVP 14: 선별 규칙 점검 (2026-10-17)

학습 실험이 없는 데이터(Lift, 사용자 파일)는 "근거 없음"으로만 나와서, 아무렇게나 고른 것처럼 보였다. 실제로는 어떤 데이터든 같은 규칙(품질 점수 + 위치 칸 배분)으로 고른다. 근거는 두 층이다.

| 근거 | 무엇을 확인하나 | 방법 | 비용 |
|---|---|---|---|
| 규칙 점검 (이번에 추가) | 품질 점수가 좋은 시범이 실제로 숙련자 시범인가 | 숙련도 라벨과 비교 | 학습 없음, 몇 초 |
| 학습 효과 (근거표) | 고른 데이터로 학습하면 무작위보다 낫고 전체와 비슷한가, 몇 개가 적당한가 | 학습 실험 | GPU 수 시간 |

규칙 점검을 통과해도 학습이 나아진다는 뜻은 아니다. 카드와 키트에 그렇게 함께 적는다.

## 판정 규칙 (Lift 결과를 보기 전에 커밋 fb1cb1b)
- 대상: 선별 후보(train) 중 숙련도 라벨(worse/okay/better)이 있는 시범. 30개 미만이거나 라벨이 한 종류면 "점검 불가"
- 품질 점수(선별과 같은 계산)와 숙련도의 스피어만 순위 상관, 부트스트랩 2000번 95% 구간
- 위쪽 끝 < 0이면 "통과", 아래쪽 끝 > 0이면 "반대", 그 밖은 "불분명"
- 신호 4개도 같은 방식으로 따로 계산해 `analysis.json`에 남긴다 (판정은 품질 점수 하나로)

## 결과
| 데이터 | 판정 | 상관 (95% 구간) | 점수 상위 절반의 better 비율 | 하위 절반 |
|---|---|---|---|---|
| Can MH | 통과 | -0.647 (-0.712 ~ -0.569) | 56% | 10% |
| Square MH | 통과 | -0.710 (-0.772 ~ -0.642) | 61% | 6% |
| **Lift MH** | **통과** | -0.709 (-0.757 ~ -0.648) | 59% | 8% |
| 라벨 없는 파일 | 점검 불가 | - | - | - |

신호별로도 세 데이터 모두 네 신호가 통과했다. 가장 약한 것은 그리퍼 여닫기 횟수다 (Can -0.29, Square -0.24, Lift -0.17). Can에서 고른 신호를 Square와 Lift에 맞춰 다시 고르지 않았다.

## 바꾼 것
- `curation_tools/rule_check.py`: `check()`(전체 결과), `compact()`(LLM 요약용, 라벨 이름과 신호별 결과 제외)
- `analyze.run`: `analysis.json`에 전체, `analysis_summary.json`에 압축본. `pending_analysis`가 압축본을 넘긴다
- Dify 진단 정리(개수 확인 카드)와 학습 키트·근거 정리에 "규칙 점검" 한 줄. 이 두 코드 노드만 바꿔 게시함 (나머지 노드는 게시본 그대로)
- 키트의 근거 없음 문구: "이 방법이 통하는지 근거가 없다" → "이렇게 고르면 학습이 나아지는지는 확인되지 않았다"

## 확인
- 테스트 6개 추가(통과·반대·불분명·라벨 없음·재현·요약에 라벨 이름 없음), 전체 통과
- 실제 대화(게시된 Dify): Lift와 Can 모두 카드와 키트에 "규칙 점검: 통과". 라벨을 지운 Lift 복사본은 "점검 불가"

## 한계
- 숙련도 라벨이 있어야 점검할 수 있다. 사용자 파일 대부분은 라벨이 없어 "점검 불가"가 나온다
- 라벨은 "사람이 매긴 숙련도"다. 숙련자 시범이 학습에 더 좋다는 가정 자체는 근거표(학습 실험)로만 확인된다
