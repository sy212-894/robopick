## 데이터 구조 (Can MH low_dim)
- 시범 300개, 총 62,756 스텝. 길이 최소 98 / 평균 209 / 중앙값 178 / 최대 1,050 → 같은 개수라도 프레임 수 차이가 커서 프레임 예산을 따로 봐야 함
- 숙련도 필터 키: `worse` / `okay` / `better` 각 100개, 운영자별 키(`better_operator_1` 등), 조합 키(`okay_better` 등)
- 분할: `train` 270 / `valid` 30, 공식 하위 집합 `20_percent`(60), `50_percent`(144)
- 관측: `obs/object` 14차원(캔 위치 3 + 회전 4 + 그리퍼 기준 상대 위치 3 + 상대 회전 4), 로봇 관절·그리퍼 상태
- `states` 71차원: 평가 때 특정 초기 상태로 되돌리기 가능
- 환경: `PickPlaceCan`, Panda, 제어 주기 20Hz, 제어기 형식 `BASIC`(robosuite 1.5) → 코랩은 robosuite `v1.5.1` 브랜치 사용 (robomimic 공식 설치 문서 기준)

## Dify ↔ 로컬 MCP 서버 연결
- 경로: Dify 컨테이너 → `http://host.docker.internal:<포트>/mcp` → 노트북의 MCP 서버(127.0.0.1에 바인딩)
- 문제 1: MCP 서버의 DNS 리바인딩 방어가 `host.docker.internal` 호스트 이름을 거절(421) → 방어는 켠 채 허용 목록에 `host.docker.internal:*` 추가 (`TransportSecuritySettings`)
- 문제 2: Dify의 SSRF 방어 프록시(squid)가 사설 주소로 가는 요청을 차단(403) → 사용자 승인 후 `C:\dify\docker\.env`에 `SSRF_PROXY_ALLOW_PRIVATE_DOMAINS=host.docker.internal` 추가, 프록시 컨테이너 2개 재생성. 백업 `.env.bak-20261011`. 되돌리려면 이 줄을 지우고 `docker compose up -d ssrf_proxy agent_ssrf_proxy`
- MCP Python SDK는 2.x에서 API가 바뀌어(`FastMCP` → `MCPServer`) **1.x로 고정** (`mcp[cli]<2`)
- 확인: 시험용 서버 `test-hello`의 `hello` 도구를 Dify 워크플로우 도구 노드에서 실행 → SUCCESS, 0.26초

## 코랩 스모크 테스트 (10/11)

### 코랩에서 해결한 문제
1. robomimic이 transformers==4.41.2 등을 고정 요구 → Python 3.13용 설치 파일이 없어 tokenizers 빌드 실패 → `--no-deps`로 설치 후 필요한 패키지만 따로 설치
2. 저장소를 /content 아래에 받으면 코랩이 sys.path 맨 앞에 넣어 둔 /content 때문에 저장소 폴더가 패키지처럼 import됨(파일 위치 None) → `/content/src`에 받고 일반 설치
3. robosuite 1.5.1이 mujoco>=3.2.3만 요구해 최신 3.15가 설치됨 → `binding_utils.get_joint_qpos_addr`에서 AssertionError → robosuite 설치 뒤 `mujoco==3.3.0`으로 강제 재설치
