# 6단계: Square로 일반화 (2026-10-12 ~ )

Can에서 만든 분석·선별·검수·학습 계획 흐름을 두 번째 데이터셋인 robomimic Square(너트를 기둥에 끼우기)에 그대로 적용했다. 목표는 두 가지다. 도구가 데이터셋 하나에 묶이지 않고 동작하는지, 그리고 Can보다 어려운 과제에서도 선별 효과가 나오는지 확인한다.

## 무엇을 바꿨나
- `analyze.py`: 데이터셋 이름(`square_mh`)과 물체 이름(캔/너트)을 파일에서 읽는다. 조건 격자는 Can과 같이 물체 초기 위치 (x, y) 분위수 3x3이다
- `select_demos.py`: 필터 키 복사본 이름을 `<데이터셋>_curated.hdf5`로 만든다
- `train_eval.py`: 데이터셋별 다운로드 경로(`DATASETS`), 학습 설정(`TRAIN_CONFIGS`), 묶음당 예상 시간(`MINUTES_BY_DATASET`), 노트북(`NOTEBOOKS`)을 둔다. Can 학습 계획 지문(c15466d53a01cedb)은 바뀌지 않았다
- `review.py`: 승인 화면의 전체 데이터 프레임 수와 예상 시간을 데이터셋에 맞게 낸다 (전에는 Can 값 56,186이 고정돼 있었다)
- `server.py`: `analyze_data`가 `can_mh`와 `square_mh`를 받는다
- 노트북 `kaggle/03_square.ipynb` (생성 스크립트 `kaggle/build_square_notebook.py`). Can 노트북은 건드리지 않았다
- Dify: Square 안내, 추천 질문, 결과 표의 중간 평가 epoch를 계획에서 읽기, 짝지은 판정 줄 추가

## 선별 (select_demos, R-20261012-square-select)
예산 150개, 조건별 비례 배분 후 칸 안에서 품질 점수(네 신호 순위 백분위 평균) 순으로 골랐다. 9칸 모두 부족 없이 채웠다.

| 묶음 | 시범 수 | 총 프레임 | 사후 라벨 (worse / okay / better) |
|---|---|---|---|
| 선별 (curated_150) | 150 | 29,892 | 18 / 48 / 84 |
| 무작위 (random_150) | 150 | 41,070 | 55 / 51 / 44 |
| 조건별 균등 무작위 | 150 | 39,377 | 50 / 51 / 49 |
| 프레임 맞춘 무작위 | 107 | 29,353 | 39 / 31 / 37 |
| 전체 (train) | 270 | 72,707 | - |

선별 결과는 better가 84개(56%)로 무작위(29%)의 약 2배이고, 프레임은 전체의 41%만 쓴다.

**검사에서 걸린 것 (칸 안 위치 쏠림)**: 선별 도구 자체 검사가 `revise`를 냈다. x2y1 칸에서 고른 시범의 평균 위치가 안 고른 시범과 2.1cm 차이 나서, 쏠림 비율 0.74가 무작위 95% 기준 0.72를 조금 넘었다. 그런데 독립 검수(`review_selection`)는 이 항목을 다시 검사하지 않아 pass가 났고, Dify 흐름에서도 그대로 승인됐다. 판단과 남은 일:
- 실험에 주는 영향은 작다고 본다. 9칸 중 1칸이 기준을 0.02 넘은 정도이고, 기준(무작위 95%)은 칸 하나 기준이라 9칸을 함께 보면 무작위로 뽑아도 한 칸쯤 넘는 일이 드물지 않다
- 대신 **검수 단계에서 이 경고가 사라진 것은 흐름의 빈틈**이다. 검수가 선별 도구의 검사 결과를 이어받아 경고로라도 보이도록 고친다 (본 실험과 무관해서 결과가 나온 뒤에 반영)
- 9칸 동시 비교에 맞게 기준을 고칠지(예: 9칸 중 최댓값의 무작위 분포로 기준 잡기)도 함께 검토한다

## 파일럿 (Kaggle T4, 2026-10-12)
전체와 무작위 두 묶음을 시드 1로 400 epoch까지 학습하고, 100 epoch마다 10번 평가했다. 결과 `results/square_mh_3b6cc7529b7e1101_pilot_kaggle.json`.

| 묶음 | 100 | 200 | 300 | 400 epoch | 학습 / 평가 시간 |
|---|---|---|---|---|---|
| 전체 (270) | 0/10 | 0/10 | 0/10 | 5/10 | 8분 / 8분 |
| 무작위 (150) | 0/10 | 0/10 | 0/10 | 5/10 | 8분 / 7분 |

- Square는 Can보다 훨씬 늦게 배운다. 300 epoch까지 한 번도 성공하지 못했고 400 epoch에서 막 성공하기 시작했다
- 400 epoch로 본 실험을 하면 데이터 차이보다 "얼마나 덜 배웠나"가 결과를 좌우할 수 있다. Can처럼 200 epoch에서 학습 속도를 비교하는 것도 모든 묶음이 0%라 의미가 없다
- 그래서 **600 epoch로 늘리고 중간 평가를 400 epoch(30번)로 옮겼다** (학습 계획 지문 3b6cc7529b7e1101 → 7d9cc28398190719). 묶음당 약 27분, 15번 실행에 약 7시간
- 평가 1번에 약 11초 걸린다. 실패한 에피소드는 400 step을 끝까지 돌아서, 성공률이 낮을수록 평가가 길어진다

노트북 수정 중 발견한 문제: 모델 저장 간격을 "첫 평가 epoch" 기준으로 잡는 식이라, 평가 시점이 [400, 600]이면 400·800 epoch만 저장되고 600 epoch 모델이 남지 않는다. 평가 epoch들의 최대공약수(200)로 저장하도록 고쳤다. 체크포인트 폴더와 결과 파일 이름에도 계획 지문을 붙여, 파일럿 모델이 본 실험에 섞이지 않게 했다.

## 본 실험 설계와 판정 기준 (결과를 보기 전에 정함, 2026-10-12)
- 5개 묶음 x 시드 1, 2, 3 = 15번 실행. 핵심 3묶음(선별·무작위·전체)의 시드 1을 먼저 돌린다. 이때 성공률이 바닥이면 멈추고 설정을 다시 정한다
- 평가: 400 epoch 30번, 600 epoch 50번. 물체 초기 위치(np)와 행동 샘플링(torch) 난수를 에피소드마다 12345+i로 고정하고, 시범마다 성공/실패를 기록한다. Can 5-10에서 배운 대로, 같은 모델은 언제 평가해도 같은 결과가 나오고 모든 모델이 같은 조건에서 비교된다
- **주 판정: 600 epoch 짝지은 비교**. 같은 시드·같은 평가 위치끼리 짝지은 차이의 95% 신뢰구간이 0을 넘고, 세 시드 모두 같은 방향일 때만 "차이 있음"
  - 선별 - 무작위: 1주차 목표 +5%p 이상
  - 전체 - 선별: 1주차 목표 하락 5%p 이내
- 보조 판정: 짝짓지 않은 비교(Can과 같은 방식), 400 epoch 학습 속도(짝지은 비교 포함), 품질 점수 효과(선별 - 조건별 균등), 칸별 배분 효과, 같은 프레임 수 비교
- 판정 무효 조건: 전체 데이터 기준선 성공률이 20% 미만이면 학습 설정 문제로 보고 판정하지 않는다
- 판정은 `train_eval.collect`가 계산하고, Dify 결과 표에도 같은 값이 나온다

## 본 실험 중간 점검과 계획 변경 (6-5, 2026-10-12)
시드 1 핵심 3묶음과 선별 시드 2까지 돈 뒤 멈췄다. 결과 `results/square_mh_7d9cc28398190719_main_partial_kaggle.json`.

| 실행 | 400 epoch (30번) | 600 epoch (50번) | 학습 / 평가 시간 |
|---|---|---|---|
| 선별 시드 1 | 8 (27%) | 11 (22%) | 13분 / 17분 |
| 무작위 시드 1 | 7 (23%) | 5 (10%) | 13분 / 17분 |
| 전체 시드 1 | 14 (47%) | 7 (14%) | 13분 / 17분 |
| 선별 시드 2 | 4 (13%) | 15 (30%) | 13분 / 16분 |

- 재현성은 정상이다. 무작위 시드 1의 400 epoch 모델이 처음 10개 위치에서 파일럿과 똑같은 결과(1000011011)를 냈다
- 600 epoch로 늘린 판단은 근거가 약했다. 같은 30개 위치에서 선별 8→4, 무작위 7→3, 전체 14→3으로 600 epoch가 오히려 낮았고, 선별 시드 2는 반대로 4→15로 올랐다. 학습 시점마다 성공률이 크게 오르내려 한 시점의 평가가 운에 좌우된다
- 전체 데이터 600 epoch가 14%로, 미리 정한 무효 기준(20% 미만)에 걸렸다
- 결정 (사용자 확인): Square는 **보조 결과**로 두고, 핵심 3묶음만 시드 2·3까지 마저 돌린다 (약 3시간). 조건별 균등·프레임 맞춘 무작위 묶음은 뺐다
- 보고 방식: 주 판정(600 epoch 짝지은 비교)과 무효 기준은 그대로 둔다. 여기에 **400·600 epoch 평가를 합친 짝지은 비교**를 보조로 더한다. 이 보조 판정은 시드 1 결과를 본 뒤 추가한 것이라, 이것만으로 결론을 내지 않는다
- 학습 방식을 바꿔 Square 성능 자체를 올리는 것(더 길게 학습하고 가장 좋은 시점 고르기 등)은 GPU 시간과 마감(10/21) 때문에 하지 않는다
