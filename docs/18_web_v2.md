# MVP 14-6단계: 웹 데모 화면 (2026-10-17)

데모 화면을 새 흐름(진단 → 사람이 개수 확정 → 선별·검수·학습 키트 → 결과 올리기 → 판정)에 맞췄다.

## 바뀐 것 (`web/src/pages/Demo.tsx`)
- 진행 단계: 질문 해석 → 근거 검색 → 에이전트 판단(analyze_data, recommend_budget 등) → 진단과 추천 → 개수 확인 → 확정 기록 → 선별 → 검수 → 학습 키트 → 보고 작성
- **개수 확인 카드** (예전 "학습 승인" 카드를 바꿈): 진단 정리 노드의 출력(데이터·선별 후보, 부족한 칸 표, 중복, 추천 개수와 근거)과 개수 입력칸(기본값 = 요청한 개수 또는 추천 개수), [이 개수로 고르기] / [취소]. 10 미만이나 정수가 아니면 보내지 않고 안내한다. 입력값은 중계 서버를 거쳐 Dify 양식 입력(`inputs.budget`)으로 간다
- **보고**: 최종 답변(보고, 학습 키트 내려받기 링크, 근거 표, 수집 계획). 예전의 "결과 조회 도구 성공률 막대"는 뺐다 (우리는 학습하지 않는다)
- **학습 결과 올리기**: 결과 파일(JSON)을 고르면 `/api/results/{대화ID}`로 보내 판정 카드를 보여 준다 (선별 효과 판정: 묶음별 성공률·신뢰구간, 선별 - 무작위, 하락 기준 / 결과 확인: 성공률과 우리 실험의 비슷한 결과)
- 예시 요청: Can 골라줘(추천 개수), Can 100개, Square 골라줘, 데이터 추천받기, 필터 키 질문
- `Markdown.tsx`: `[글자](주소)` 링크를 그린다. 이 서버의 `/api/` 주소와 http(s) 주소만 연다
- `Runs.tsx`: 실행 기록에 "학습 키트 만듦", "사용자가 올린 학습 결과 판정" 표시
- 판정 안내 문구를 존댓말로 (`judge.py`, `judge_results`의 결과 없음 안내)

## 화면에서 확인 (브라우저, 중계 서버 + 게시된 Dify)
- [Can 골라줘] → 카드: 부족한 칸 4개 표, 중복 0쌍, 추천 135개, 입력칸 135
- [이 개수로 고르기] → 단계가 모두 초록(선별 0.4초, 검수 0.2초, 키트 0.2초, 보고 1.7초) → 보고에 키트 링크 5개 (노트북 내려받기 200, 셀 9개)
- 결과 올리기(노트북 형식의 비교 학습 결과: 선별 86%, 무작위 62%, 전체 80%) → 선별 효과 판정: 선별 - 무작위 +24.0%p 차이 있음, 하락 기준 충족, 우리 실험의 비슷한 결과(Can 135: 88/82/75%), 시드 1개 주의
- 실제 학습 결과로 올려 보는 것은 7단계(키트를 Kaggle에서 실제로 돌림)에서 한다
